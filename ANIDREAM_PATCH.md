# AniDream patch для Anima-Standalone-Trainer

Изменённые файлы (все правки помечены комментарием `[AniDream patch]`):
- `training-ui/server.js`
- `training-ui/public/index.html`
- `training-ui/public/js/app.js`
- `networks/lora_anima.py` (раздел 6)

Это личный форк. Upstream, на котором основан патч, — коммит `7f5c336`; все правки — отдельные коммиты поверх него.
Обновиться с upstream: добавить его как remote `upstream`, затем `git fetch upstream` → `git merge upstream/main`.

## 1. Своя модель (DiT) у каждой задачи
- Вкладка Network → поле «Base Model (DiT) for this job». Пусто = глобальная модель (старые задачи работают как раньше).
- Выпадающий список: модели >1 ГБ из папки глобальной DiT и из папок, указанных в Global Settings → Application → «Model folders for job picker» (плюс один уровень подпапок).
- Хранится в `config.toml` задачи как `[model_override] dit_path = "..."`.
- Если файла нет — обучение не стартует, с понятной ошибкой.
- Генерация сэмплов из интерфейса тоже использует модель задачи.

## 2. Баги с нулями
- Text Encoder LR: 0 больше не подменяется на 5e-5 при открытии задачи (`||` → `??`).
- Network Alpha: можно 0 (= как dim) и дробные значения.
- Save every N epochs / steps: можно 0 = сохранять только финальную модель (сервер не передаёт 0 в sd-scripts, там было бы деление на ноль).
- Max Grad Norm: новое поле (раньше жёстко 1.0). 0 = клиппинг выключен.

## 3. Скрытые настройки LoRA (вкладка Network → «Advanced (Anima LoRA)»)
Пишутся в `network_args`, старые задачи открываются как раньше (известные ключи из поля Network Args переезжают в поля).
- Blocks to Train (`train_block_indices`), например `14-27`.
- Ранг по типам слоёв: Self-Attn / Cross-Attn / MLP / Modulation (`self_attn_dim` …), 0 = не обучать этот тип.
- LoRA+ (`loraplus_lr_ratio`), Rank Dropout, Module Dropout.
- Train LLM Adapter (`train_llm_adapter=True`).

## 4. Ещё в настройках обучения
- FP8 Base Model (экспериментально, `fp8_base`) — экономит ~2 ГБ VRAM.
- Validation Split / Validate Every N Steps — validation loss в TensorBoard.
- Подсказка у Flash Attention: без пакета flash-attn галочка ничего не делает.

## 5. Disk Usage & Cleanup (вкладка с Test Generation)
- Сколько места занимают чекпоинты, состояния оптимизатора и сэмплы.
- Галочки «оставить» у чекпоинтов (по умолчанию финальный и последний шаг), удаление старых `-stepNNN-state`.
- Последний `-state` не удаляется без отдельной галочки (иначе не будет Auto-resume).
- Удаление только после подтверждения со списком файлов; во время обучения запрещено.

## 6. LoKr / LoHa / DoRA (вкладка Network → Advanced → Network Type)
- Network Type: LoRA (как раньше), LoKr, LoHa (оба LyCORIS-совместимые) или DoRA. Пишется в `network_args` как `algo=lokr|loha|dora`, для LoKr ещё `factor=N`.
- LoKr — персонаж в одном стиле (меньше тащит стиль), LR обычно выше, чем у LoRA. Factor 8–16 или -1 = авто; очень большой Network Dim (например 100000) = полные матрицы.
- LoHa — стили художников (больше мелких деталей при том же dim), dim 8–16, перегорает легче.
- DoRA — LoRA + обучаемая «сила» правки (`dora_scale`), точнее держит персонажа, обучение медленнее.
- Ключи стандартные (LoKr: `lokr_w1`, `lokr_w2`/`lokr_w2_a`+`lokr_w2_b`; LoHa: `hada_w1_a/b`, `hada_w2_a/b`; DoRA: `lora_down/up` + `dora_scale`): ComfyUI / SwarmUI грузят без плагинов, AnimaMerger тоже (DoRA — с моделью, во вкладке «Вшить LoRA»).
- LoRA+ работает только с LoRA и DoRA, Rank Dropout — только с LoRA. Только обычное обучение на одной видеокарте (не TP/SP).
- Test Generation в интерфейсе понимает все эти файлы.

## 7. Пресеты и калькулятор шагов (вкладка Training, самый верх)
- «What are you training?»: стиль (LoRA / LoHa), персонаж (LoRA / LoKr для датасета в одном стиле / DoRA), объект, концепт, концепт-тулкит.
- «Apply preset» ставит тип сети, dim/alpha, LR (кроме Prodigy/DAdapt — там LR не трогается) и flow shift 3, и показывает подсказку по подписям для этого типа. Оптимизатор, разрешение и блоки не меняет. Всё можно поправить руками после.
- Калькулятор: «Count» считает картинки (× повторы) в папках вкладки Dataset и показывает, у скольких нет подписи; эпохи берутся из пресета.
  Шаги = картинки × эпохи ÷ (batch × accumulation), округление до 50, в пределах минимума/максимума пресета. Сохранение ≈ шаги/8, сэмплы ≈ шаги/6 (не чаще 250).
- Галочка «Base already knows it»: если персонаж/стиль/концепт уже есть в Anima под своим тегом — dim/alpha вдвое меньше (не ниже 8/4, у LoKr не меняется), эпохи и пределы шагов ×0.6, в подсказке — как выбрать триггер (родной тег базы) и что проверить до и во время обучения.
- Пределы шагов пресета считаются с учётом batch × accumulation.
- «Fill in steps» переключает на Steps и вписывает Max Steps / Save Every / Sample Every. Дальше обычный Save.
- Работает без интернета: всё внутри интерфейса, подсчёт картинок — новый запрос сервера `/api/count-images` (после обновления перезапустить интерфейс).

## 8. Очередь обучения (боковая панель Jobs, внизу)

Запускает обучения одно за другим, например несколько LoRA на ночь.

- **＋ Queue** (рядом с ▶ Train) добавляет открытую задачу в очередь. Несохранённые изменения сначала сохраняются.
- **▶ Start** запускает очередь. Если обучение уже идёт (запущено вручную), очередь дождётся его конца и продолжит.
- **⏸ Pause** — больше не запускать новые задачи; текущее обучение продолжается.
- ▲ ▼ меняют порядок, ✕ убирает задачу, **Clear** убирает все ожидающие.
- Когда обучение заканчивается, следующее стартует примерно через 8 секунд, чтобы видеокарта успела освободить память.
- **Stop on error**: если задача упала (код выхода не 0), очередь встаёт на паузу, а не идёт дальше.
- ⏹ Stop на задаче, которую запустила очередь, ставит очередь на паузу (к следующей задаче она не переходит).
- Очередь хранится в `training-ui/queue.json` и переживает перезапуск интерфейса, но сама после перезапуска не стартует: нужно снова нажать ▶ Start.

API сервера: `GET /api/queue`, `POST /api/queue/{add,remove,move,clear,start,pause,options}`. Логика запуска обучения вынесена в `startTrainingJob()`, ей пользуются и кнопка Train, и очередь; кнопка работает как раньше.
